# FocusDeck 1.10.0 implementation and verification

Cumulative progress now works alongside the existing streak ledger. The native Compose overview/detail use the supplied visual references and real persisted values. Android/desktop version is 1.10.0; Android versionCode is 15, with the application ID unchanged. Work is on local branch `codex/achievements-progress-motion`. No source push, remote build, phone installation or desktop service setup was performed.

## Requested implementation report

1. **Files changed.** Native: `Achievements.kt`, `AchievementScreen.kt`, `AchievementCards.kt`, new `AchievementMotion.kt`, `DeckRepository.kt`, `DeckNetwork.kt`, `Models.kt`, `MainActivity.kt`, `app/build.gradle.kts`, `AchievementUiTest.kt`, new `AchievementProgressTest.kt`. Desktop: `achievements.py`, `server.py`, `__init__.py`, `pyproject.toml`, new `test_progress.py`, `test_schemas.py`, `test_focusdeck.py`. Protocol: new `achievement-command-v3.schema.json`, aggregate achievement schema and wire capability schema. Added three progress examples, approved images under `docs/design/`, verification logs, this report, and updated README, AGENTS, current status and GPT/protocol instructions.
2. **Achievement schema.** Definitions gain independent `streak_enabled` (default true), `progress_enabled` (default false), and optional `progress`. Initial input accepts `current_value`, `target_value`, `unit`; stored progress also has `completed_at`, update timestamp/id. At least one capability is required. Dynamic manual cards use the shared visual components across all categories. Existing immutable built-in streak measurement rules remain protected. Abstinence progress is deliberately rejected because that kind measures elapsed time; create a separate daily/scheduled progress card if needed.
3. **Persistence.** Extended the existing `achievements_v1` DataStore JSON ledger; no Room database or parallel achievement store. `progressHistory` retains id, achievement id, timestamp, previous/new total, current/previous target, delta, unit, source and completion timestamp. A one-time `progressMigration` adds German/Custom Compute defaults without recreating deleted cards or replacing activity/history/layout. Archived goals retain history. Explicit confirmed permanent deletion removes that card's progress history and retires its command receipts. StoredDeck gains the saved motion preference.
4. **Desktop/GPT protocol.** Command contract 3 supports `progress_set` and `progress_increment`; upsert supports capability flags and initial progress. Contracts 1/2 remain accepted. Hello advertises `[1,2,3]`, and existing transport gates commands by negotiated capability. Wire/pairing stays 1; session/report stays 1/2; storage/snapshot stays 1 with additive fields. Snapshots now include progress data, percentage and completion. Existing `achievements list` and `history ID` query the timestamped PC cache; history adds `progress_history`.
5. **Progress engine.** Generic finite, nonnegative current values and positive targets, bounded to 1e12. Targets of zero/negative/nonfinite values are rejected; the renderer additionally guards division by zero. Percentage clamps to 0–100 while retaining actual over-target totals. A meaningful total/target/unit change appends history. SET merges supplied fields and is ordered by timestamp/id; stale SETs preserve newer totals while recording the receipt. Stable command IDs deduplicate SETs/increments and reject conflicting reuse. Unique equal-timestamp increments apply once even with reverse lexical IDs; older increments are rejected. Completion records a timestamp, keeps the card, and settles green. Explicit target expansion can reopen the goal without losing earlier history. Progress does not invent daily completed activity.
6. **Progress-only Compose.** Shared `AchievementTile` renders a cumulative ring, total, unit and completion treatment and omits streak statistics. Detail omits the streak graph/history and displays cumulative history. Fresh German is 0/1250 words; the tested 200/1250 case displays 16%. Values from reference images are not seeded as real activity.
7. **Hybrid Compose.** One card contains both systems. Compact uses a two-column tile layout; Wide uses a horizontal ring/content arrangement; Full-width uses the larger tile/ring hierarchy. Current/Best/signed Gap remain for streak-enabled cards. Custom Compute starts with an unset target and `index topics`; GPT supplies its actual total. Tested 20/100 then 73/146 transitions require no APK update. UI progress is generic; German's vocabulary panel label is supplied through definition metadata.
8. **Detail progress and history.** Integrated linear progress panel, percentage, completion/target-needed state, existing streak statistics, chronological bar chart, dotted Best/Average references, selected bar metadata, Today and inline Detailed History on one scrollable screen. Added retained progress history below it. Selected metadata includes progress delta/daily average and explicit activity counts when available. Focus blocks/time are labeled **day totals**: the existing ledger measures global daily focus and cannot truthfully attribute it to a particular project. No Share or separate full-history button was added.
9. **Animation changes.** Finite entry fade/translation/stagger, synchronized horizontal pager/tab underline, animated grid placement, 1.03 drag lift and spring settle, responsive card/ring sizing, archive/delete shrink/fade/translation, restore appearance, interpolated ring/numbers/overview, cyan-to-green completion/record state, deduplicated single pulse, chart entry and selected metadata crossfade/size transition. Haptics occur on long press, successful drop, unseen record/completion and daily-target completion. No infinite transitions, particles, database writes per animation frame or new timer polling.
10. **Motion preference.** Full/Reduced/Off saved in Display & connection settings, default Full. Reduced uses 120ms transitions without decorative pulses/lift/translation; Off uses immediate state changes. Android animator scale zero selects Off. Motion covers the achievement surfaces introduced here; existing timer/reward graphics remain governed by their existing UI.
11. **Existing management.** Preserved generic creation, dynamic categories, persistent order/size, archive/restore/confirmed delete, deletion tombstones, retired receipts, immutable built-in rules and current/future target removal guards. Kept midnight latest-target evaluation and independent actual activity. Existing 40 achievement engine regressions pass; new tests cover progress surviving management, migration and legacy project edits. Drag/swipe/resize are implemented and compile; actual touch behavior has not been device-executed.
12. **Tests run.** All 148 native JVM tests pass, including 40 existing achievement tests and 17 new progress/capability tests. Desktop collected 148: 147 pass, one AF_UNIX host restriction skip. Draft-2020-12 schemas and examples, invalid capability/value combinations, cached progress history and real TLS progress negotiation/delivery/snapshot round-trip pass. Seven battery measurement-tool fixture tests pass; they do not measure battery consumption. Six instrumented UI tests compile but were not executed. Git whitespace check passes. Exact logs are in `docs/verification/`.
13. **Build result.** Debug APK assembly and instrumented-test Kotlin compilation succeed. Android lint completes with zero errors and five existing warnings; the complete lint result is included. No release-signed APK was produced.

## Example desktop commands

```bash
focusdeck achievements validate examples/achievements/german-progress-v3.json
focusdeck achievements list
focusdeck achievements history german
```

For real writes, generate a current timestamp and stable unique command id from confirmed learning state, then send through `focusdeck achievements apply FILE` or stdin. The included 20/100 Custom Compute value is an example, not the real master-index size. Read `docs/GPT_ACHIEVEMENTS_INSTRUCTIONS.md` for generation/retry rules.

## Compatibility decisions

The actual daily/streak engine is retained. Historical focus measurements cannot be reconstructed as project-specific measurements, so the detail reports day totals explicitly. Progress history is persisted/rendered; a separate trend chart remains optional and was not added. Reference images are checked in as design references and are never used as screen backgrounds.
