# FocusDeck 1.22.0 · supplied three-year Developer Mode dataset

Android source is 1.22.0 / versionCode 26 on the existing local `codex/omss-native-ui` branch. This extends the existing uncommitted 1.21.0 implementation; desktop remains 1.20.0. The production phone installation remains unchanged. Only the already-isolated `.visualtest` package is deployed for this verification.

## Data and ownership

The supplied `FocusDeck_DeveloperMode_3Years_v1.22.0.zip` was safely extracted to `fixtures/developer-mode-3years/FocusDeck_DeveloperMode_3Years/`. README, manifest and schema notes were read before integration. Its included validator passed before integration and again afterward: 1,097 dates (2023-10-12 through 2026-10-12), 1,321 session plans, 2,832 focus blocks, 15,206 timeline/feed records, 5,083 achievement events, 190 Index topics and 125 Index events. The generator was **not run**. Original records, checksums, validator and optional regeneration utility are retained unchanged.

`SyntheticDataset.kt` is an asset reader and adapter with no repository, archive, transport or mutation API. It validates manifest safety markers, every included SHA-256 and byte count before exposing data, parses JSONL with streaming readers on a worker dispatcher and maps into the existing Report, CalendarDataset, AchievementStore and IndexLedger presentation boundaries. Assets are included in Android so the existing Developer Mode switch works without importing a production backup. The fixture manifest's sandbox recommendations do not authorize executing its generator or importing records; the user's request explicitly authorizes this read-only interactive Developer Mode as well as isolated device QA.

The shared `SyntheticPreview.kt` routes Home, Analytics Day/Week/Month/Year/All, Achievements/detail, Index/detail, History, expanded Timeline and Session Summary to the same native components. `VisualTestDataProvider.threeYears` exposes the adapter to the existing QA variant. No second fixture framework, database schema or synthetic command path was added. `.visualtest` still has a plain Application, no production Activity/service and no INTERNET permission. Its launcher defaults to the supplied dataset; existing named visual fixtures remain available explicitly.

When the saved Developer Mode flag is enabled, MainActivity selects this entire preview branch before composing production page callbacks. **Use real data / Disable Developer Mode** turns off only that preference and returns to the unchanged repository-backed views. The previous ephemeral card sandbox remains available inside the preview. Read-only card/Index guards and ephemeral layout preferences remain active. Real timer/service state is never replaced by fixture state. Synthetic records are never passed to repository commands, capture/finalize, archive import/save, deletion, pairing, transport or rewards. Summary Save/Copy/Send controls and History archive controls are omitted; the report document-result callback also rejects synthetic exports. Analytics export callbacks have no production destination.

## Mapping and calculation contracts

- Fixed clock: **2026-10-12 23:59:30 Europe/Berlin**. Every preview page/dialog identifies synthetic ownership and the simulated date; historical activity is not presented as today's real activity. Active/paused scene counters are frozen snapshots, not an independently running timer.
- The supplied daily/hourly aggregates drive calendar navigation and Home; the 199 period summaries reconcile to daily rows and provide the weekly Home cache. Native CalendarAnalytics allocation is checked against **every daily focus total and each of its 24 bins** before cached data is accepted. Explicit pause and break intervals retain original timestamps and source zone. Native DST splitting, Plan Execution, calibration, hourly references, duration accuracy and Focus Ratio formulas are reused. Positive start deviation remains late.
- Unknown dates have no measured CalendarDay; observed-zero dates retain a complete zero day. No absent measurement becomes a fabricated zero. Full known historical intervals support hourly averages; current-date/provisional performance closure still uses the native fixed-clock rules.
- **1,299 actual attempts** map to Reports. The other 22 supplied plans have null actual start and remain calendar-only skipped/unstarted evidence, rather than receiving fabricated session reports. Skip action timestamps locate descriptive events; the corresponding activity's actual start/end stay null. NOT_STARTED blocks remain plan metadata; only source DONE outcomes receive completion credit. Measured skipped/stopped effort is retained. Stopwatch targets stay null.
- Native block timeline counters are projections of the supplied focus/pause intervals. They are synthetic elapsed counters, not evidence of measurements made on real hardware. Supplied descriptive GPT/card/reward/status events remain in the original History feed; they never execute commands or rewards.
- Achievements replay explicit confirmations and progress deltas. Progress and streak snapshots are checked against replay. `ach_ptfs_index` uses the pack's explicit projection from the synthetic PTfS Index replay; no topic activity is inferred from titles. Both Index ledgers retain topic names, sections, reopen events and original IDs. Topic completion does not imply a study-day confirmation; the standalone Index cards have no daily-study evidence and remain neutral. Progress without a supplied unit remains `units`. Native streak/record-gap calculations remain authoritative: best **completed** history and today's pending-day behavior can differ from a portable snapshot that includes an unclosed record.
- The fixture contains no full GPT quality/comparison/reward contracts. Pace, BeatScore, PB and policy-dependent results remain N/A rather than inventing policies from project weights or fixture quality counts. The measured Overall Focus Ratio uses the existing native formula. Full-session Planned/accuracy remain N/A when the portable input supplies only a focus estimate plus observed breaks; the known focus estimate remains available in block details and the existing known timed planned portion. No planned break duration or block schedule endpoint is fabricated.
- History retains **one page of at most 80 records** in Compose state; Previous/Next, category/search/date filters and both orders stream the original feed. Ascending scans retain only their result page. Stable IDs, source-zone dates and exact attempt keys connect events to summaries. Timeline bands and expanded Summary events retain the existing lazy lists. Large title, empty, zero, idle, active, paused and early-ended presets use the supplied scenarios.

## Reproduce

```bash
python3 fixtures/developer-mode-3years/FocusDeck_DeveloperMode_3Years/validate_fixtures.py
JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ANDROID_HOME="$HOME/Android/Sdk" \
  bash scripts/build-android.sh visualtest
adb -s R3CX90NC7HR install -r android/app/build/outputs/apk/visualtest/app-visualtest.apk
python3 scripts/capture-locked-ui.py --serial R3CX90NC7HR --no-build \
  --fixture REFERENCE_3Y --screens home day week month year achievements index history timeline summary \
  --out artifacts/uiqa/developer-3years/review
```

Use `--scenario active|paused|empty|zero|long_text|ended_early`, `--motion FULL|REDUCED|OFF`, `--orientation landscape` and `--font-scale 1.4` for existing QA controls. These affect only the isolated composition, not global phone display settings. Optional regeneration remains the included `generate_fixtures.py`, to be invoked explicitly in a disposable copy followed by validation; it is not part of builds or app startup.
