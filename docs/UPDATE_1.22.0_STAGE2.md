# FocusDeck 1.22.0 · Stage 2 navigation and pairing

This continues the supplied-dataset integration and existing OMSS implementation on `codex/omss-native-ui`. Android stays **1.22.0 / code 26** for this same proposed release. Desktop advances independently to **1.21.0** for QR pairing. Future completed Android patches must increment both versionName and versionCode. No persisted-data, timer, report or achievement contract version changed.

The user explicitly requested the GitHub push, superseding the prior local-only direction. Stage 1 and preceding finalized source were pushed as `0a6fe3a` to `SydAayaat/FocusDeck`, development branch `codex/omss-native-ui`; main is not merged. The production phone is not installed, launched, re-paired, cleared or uninstalled during Stage 2. Only the existing `.visualtest` app/test packages are installed on USB Samsung SM-S928B `R3CX90NC7HR`. No emulator or release APK/upload is used.

## Behavior

- Home keeps its existing header/overflow. Real and synthetic views can reach Display settings, Developer Mode settings, Pair desktop, Devices and existing Sounds. Devices shows the actual saved desktop/role/connection and existing connect/disconnect/pair callbacks, without exposing the permanent token. Appearance, motion and immersive changes use the existing preference handlers. Preview host controls have no synthetic-record mutation route.
- The obsolete four-icon top navigation is removed from Analytics, Achievements and session/reward scaffolding, plus the legacy QA path. Existing shortcuts, overflow destinations, achievement Home control and nonimmersive bottom navigation remain.
- Android’s Back dispatcher keeps native popups/dialogs and nested detail/drill/layout handlers ahead of root navigation. Top-level Analytics Back returns to Home. Home first Back shows exactly **Swipe again to exit the app**; a second within two seconds calls Activity.finish. The timeout starts a new confirmation window. No timer/service/process termination is added.
- Root destination/dialog flags, Analytics period/date, drill stack and window, sorting, month/metric, achievement category/selected card/archived filter, paged History filters/search/page, report key, Timeline date/event disclosures and report event disclosures survive configuration recreation. Native lazy-list savers preserve relevant scroll. Reports are resolved by stable key against canonical history rather than serializing private report payloads into saved state. The timer remains in the existing application repository. `.visualtest` accepts unspecified automatic rotation; explicit capture orientation applies only on first creation.
- The actual Achievements page has no calendar/date granularity. Hax selected the **existing Analytics date control** for the shortcut. Normal tap still opens its picker. Long press sets only the anchor to the genuine device-local date and keeps Day/Week/Month/Year selected; source-week rules remain Monday-first. Synthetic preview uses its labeled fixed simulated date instead.
- Time Estimation Accuracy loses its Daily Timeline/Session Detail disclosure and associated spacing, reducing the default Day card height from 270 to 170 dp. No By Project Type shortcut remains in that card. Existing metrics, calculations, other finalized cards and the separately accessible Daily Timeline remain.
- Local QR pairing uses two-minute crypto-random, single-use, role-bound invitations, pinned TLS redemption, authenticated ordinary hello, explicit trust review and expected-existing trust guards. Manual JSON remains independently accessible, including with an older host that lacks invitations. Camera denial, cancellation, invalid/expired/used/revoked/version-mismatched invitations, unreachable host, already-paired clients and interrupted pairing have informative states. See [PAIRING_INVITATIONS.md](PAIRING_INVITATIONS.md).
- Supplied fixtures, asset adapter, aggregate formulas, fixed clock, paging and export/sync/reward isolation remain. The validator is rerun; the generator is not run. Disabling Developer Mode uses the existing genuine repository view. Test settings are ephemeral and all pairing/network writes are blocked in `.visualtest`.
